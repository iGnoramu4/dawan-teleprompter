# 代码评审清单

> 状态：生效 ｜ 责任人：TL ｜ 适用于所有 PR

## 1. 评审目标（按优先级）

1. 正确性：边界、空值、权限、失败路径；
2. 数据安全与隐私：不泄露台本、音频、凭据；
3. 可维护性：分层、命名、复用、可测试；
4. 性能：主线程预算、内存（包体只记录，见下）；
5. 一致性：规范、文档、文案、主题令牌。

风格问题不阻塞合并（由 `dart format` / lint 自动处理），评审不应围绕空格与引号反复拉扯。

## 2. 必查项（Blocking）

### 功能与逻辑

- [ ] 有对应 issue/需求，PR 描述说明"为什么"；
- [ ] 新增逻辑有测试；修复缺陷有可复现用例；
- [ ] 权限拒绝、无设备、模型缺失、存储不足等失败路径已处理；
- [ ] 不引入与计划文档范围冲突的功能。

### 分层与依赖

- [ ] `core_*` 未 import Flutter / 平台包；
- [ ] 无 `features/a → features/b` 的横向依赖；
- [ ] 业务逻辑未下沉到原生层；
- [ ] 新增依赖符合 [DEPENDENCY_POLICY.md](./DEPENDENCY_POLICY.md)。

### 数据与隐私

- [ ] 日志无台本正文、识别原文、音频、token、硬件 ID；
- [ ] release 不输出 debug 日志；
- [ ] 网络能力默认关闭，开启时才监听/连接；
- [ ] 外部入参（DeepLink/分享）走白名单、大小限制、隔离目录；
- [ ] 敏感值存安全存储，不落明文。

### 安全

- [ ] 无硬编码密钥/令牌；
- [ ] 传输走 TLS（若涉及非回环通信）；
- [ ] 服务端接口（若未来引入）有签名、时间窗、nonce；
- [ ] 文件解析限制大小、拒绝未知类型。

### UI 与无障碍

- [ ] 壳层使用 M3 组件与 `design_system` 令牌，无硬编码颜色/字号；
- [ ] 图标按钮有 tooltip/semanticLabel；
- [ ] 触控目标 ≥ 48 dp（遥控 ≥ 56 dp）；
- [ ] 深浅色、动态取色、200% 字号下不溢出；
- [ ] 新增文案走 ARB，中英同步。

### 性能

- [ ] 无 `build` 内重计算、无每帧 `setState`；
- [ ] 长列表用 builder；大对象及时释放；
- [ ] 新增资源/依赖的包体增量有记录（> 1 MB 需说明来源与许可，**不作为阻塞项**）。

### 兼容与迁移

- [ ] 数据库变更带迁移与回滚测试；
- [ ] 协议/通道变更版本化，Dart 与原生同 PR；
- [ ] 旧版本数据可读或给出明确迁移提示。

### 文档同步（见 DOCUMENTATION_POLICY.md §4）

- [ ] 行为/接口/权限/架构变更已更新对应文档；
- [ ] `CHANGELOG.md` 有 `Unreleased` 条目（用户可感知变化）；
- [ ] ADR 已新增或更新（不可逆决策）。

## 3. 建议项（Non-blocking）

- 可进一步复用的现有组件/库；
- 可简化的条件分支或状态；
- 可补充的注释（仅复杂算法）；
- 可改善的命名（不要求全库重命名）。

## 4. 评审结论

| 结论 | 含义 | 动作 |
|---|---|---|
| Approve | 可合并 |  squash merge |
| Approve with nits | 小问题，作者自行处理 | 不阻塞 |
| Request changes | 存在 Blocking 项 | 修复后重评 |
| Reject | 方向错误/范围冲突 | 关闭并说明 |

## 5. PR 描述模板

```markdown
## 改了什么
## 为什么
## 怎么验证
- [ ] 单测/组件测试
- [ ] 真机（设备/系统/场景）
- [ ] 手动步骤
## 文档影响
- [ ] 无
- [ ] 已更新：<文件>
## 风险与回滚
```

## 6. 敏感模块附加要求

`core_alignment`、`asr_kit`、`tp_platform`、网络与权限相关代码：

- 2 名评审人，其中 1 名熟悉该模块；
- 必须附评测/性能数据或真机记录；
- 涉及安全策略的变更需在 PR 中引用威胁与缓解措施。
