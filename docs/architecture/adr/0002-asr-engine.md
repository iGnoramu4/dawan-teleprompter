# 0002. ASR 引擎：sherpa-onnx 主 + Vosk 兜底 + whisper.cpp 离线精对齐

- 状态：Accepted
- 日期：2026-11-06
- 决策人：ALG
- 关联：计划文档 §5.1–§5.10、§10.2、§17 D2

> **2026-11-06 更新**：性能定位改为中高端基准（ADR-0005）。「低端/内存不足时 Vosk 兜底」不再作为需求或门禁项；T1/T2 双档模型也不以为低端让步为目标，可简化为单档。当前实现为 `zipformer-zh-14M-int8`，Vosk 与双档切换均未接入。

## 背景

提词器需要**真流式、完全离线、低延迟**的中英识别，并把识别文本用于单调对齐。约束：模型随包分发、运行期零下载、三端可用、许可允许分发、低端设备可降级。

参照实现（小白提词器）采用端侧 sherpa-ncnn 流式 Transducer，内嵌 145 MB 中英模型，16k/mono/PCM16，`VOICE_RECOGNITION` 音频源，端点 2.4 s / 1.0 s / 30 s，单线程、关闭 GPU，并在 Application 启动时预热。其拼音模糊命中率匹配（阈值 `0.55+0.05*e`、55 条混淆表、滑窗前看 1..N 行）只做**行级游标**，存在重复计数导致命中率 >1.0、短行误命中、行内位置缺失三个缺陷。

## 决策

1. **主引擎**：`sherpa-onnx` streaming zipformer transducer（int8），双档模型（T1 轻量 / T2 标准），运行期切换；
2. **兜底**：Vosk 小模型（低端/内存不足时），保持可离线；
3. **离线精对齐**：`whisper.cpp` 仅用于**录制后**对齐与评测，不参与实时跟随；
4. **不采用** sherpa-ncnn 作为主引擎（桌面支持弱、权重与工具链不可复用）；
5. **对齐层**沿用参照实现的思路：无声调拼音 + 55 条混淆表 + 命中率预筛 `0.55+0.05*e` + 滑窗前看，但**去重命中**修复重复计数，并用**词级 DP**补足行内位置。

## 备选方案

| 方案 | 模型体积 | 精度 | 流式 | 许可/移植 | 结论 |
|---|---|---|---|---|---|
| sherpa-onnx zipformer | T1 约 40–60 MB / T2 约 120–180 MB | 中英混读稳，专有名词可调 | 真流式 | Apache-2.0，官方 Flutter 绑定，三端成熟 | **主引擎** |
| sherpa-ncnn（参照实现） | 145 MB 单档 | 接近，但不可调 | 真流式 | 桌面/Flutter 支持弱，权重不可复用 | 仅借鉴参数 |
| Vosk | 小（约 30–50 MB） | 低于 zipformer | 流式 | Apache-2.0，生态成熟 | **兜底** |
| whisper.cpp | 中/大 | 离线精度高 | 非流式 | MIT，CPU 推理慢 | **仅离线精对齐/评测** |
| 系统识别 | 0 | 高 | 是 | 可能走云端、长时需重启 session | 因离线承诺排除 |
| 云端 ASR | 0 | 最高 | 是 | 违反离线/隐私 | 排除 |

## 影响

正面：

- 三端同一接口，模型可替换；低端有降级路径；
- 拼音预筛把 DP 候选窗口压到很小，CPU 可控；
- 录制后可用 whisper.cpp 做高质量复盘对齐，不影响实时链路。

负面：

- 双档模型增加包体与测试矩阵；
- 权重许可需逐项核对（D2），不可再分发者改为本地导入；
- 混淆表需长期维护（数据驱动、可单测）。

## 验证方式

- M0：三端实时率 ≥ 5×、内存 < 400 MB、首字延迟 ≤ 500 ms；
- 评测集 60 段：稳态误差 ≤ 0.5 行、跳读收敛 ≤ 2 句、静音误滚动 < 1 次/30 min、口误回跳 0；
- 与参照实现的参数对照实验：命中率预筛阈值与混淆表对精度/延迟的影响记录在评测报告。
