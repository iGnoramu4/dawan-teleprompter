# 0004. 取消包体门禁；阅读页嵌入完整思源黑体超粗体

- 状态：Accepted
- 日期：2026-11-06
- 决策人：产品 / TL
- 关联：计划文档 §3.3、§14.4、§19；TESTING.md §6、§8；I18N.md §4

## 背景

1. 早期计划把「Android 单 ABI ≤ 120 MB」等体积目标写成了发布门禁，导致团队倾向拆 ABI、裁资源、做字体子集，增加构建与维护复杂度，却对核心链路（识别→对齐→滚动）稳定性没有帮助。
2. 阅读页需要舞台/分光镜场景下足够醒目的正文；系统默认字体在大字号、远距离、镜像条件下偏细，希望使用超粗体（weight 900）。
3. 内置 14M ASR 模型已使 APK 远超旧体积目标，体积妥协不再有意义；当前优先级为**稳定、易用、开发方便**。

## 决策

- **体积只记录，不设上限、不作为合并/发布门禁**；不为压体积拆 ABI、裁资源或做字体子集。
- 阅读页嵌入 **Source Han Sans SC Heavy（同源 Noto Sans SC Black，weight 900）** 完整字体，不做子集裁剪。
- 字体以 Flutter 字体资产打包（`apps/app/assets/fonts/` + `pubspec.yaml` `fonts:`），`design_system` 提供 `TpTokens.readerFontFamily` / `readerFontWeight`；编辑页与设置页保持 Material 默认字体。
- 许可：SIL OFL 1.1；许可全文随包（`assets/licenses/`），来源、SHA256、大小登记在 `NOTICE` 与 `DEPENDENCY_POLICY.md §7`。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 维持 120 MB 门禁 + 拆 ABI/裁资源 | 安装包小 | 构建复杂、维护成本高、收益与稳定性无关 | 否决 |
| 字体子集（约 7000 字） | 体积小 | 生僻字缺字风险、维护子集脚本、舞台场景不可接受方框 | 否决 |
| 完整 Heavy 字体 + 体积只记录 | 字形完整、渲染一致、开发简单 | 包体与内存增加约 10 MB | **采用** |

## 影响

正面：字形完整、阅读页辨识度提升；构建链保持单一通用包；无子集维护负担。

负面：APK 增加约 10 MB；阅读页首次排版加载完整字体，PSS 实测增加约 26.7 MB（含页面本身）；需要长期保留 OFL 许可与来源记录。

## 验证方式

- `docs/testing/records/20261106-m2.md`：混排（中文/标点/数字/英文）、44/88 px、行距、镜像、高亮回归；
- 冷启动（到首页）三次实测 557–571 ms，仍满足 < 1.5 s；
- `NOTICE`、`assets/licenses/NotoSansSC-OFL.txt` 随包存在，SHA256 与登记一致。
