## 1. 改了什么

| 项 | 实现 |
| --- | --- |
| 对齐单位 | 音节。中文一字 = 1 音节；英文术语整体 1 token |
| 读音归一化 | lpinyin 无声调拼音 → 模糊等价类（zh/ch/sh→z/c/s、n→l、uang/iang→uan/ian、ing/eng/ang→in/en/an） |
| 多音字 | 保留全部读音，比较取交集；词语表（如「银行」）提供上下文主读音；声调只作 0.1 加分项 |
| 数字 | 先转中文口播读法：`12.5%` → `百分之十二点五`，再按音节切分 |
| 英文 | 整体一个 token；识别流拆开时（`S D K`）按术语表合并回 `sdk` |
| 分词边界 | token 按字（音节）生成，合词/拆字结果一致 |
| 界面回填 | 决策用音节，落位仍用 `srcStart/srcEnd` 字符偏移（视觉行 + 段内字符锚点） |
| 回退开关 | 设置 →「按读音近似匹配」，默认开；关闭即逐字文字匹配，跟读中切换热替换对齐器 |

### 代价 / span / 置信度新语义

- 替换、漏读、多读：各 1 个音节错误（旧 1.0 / 1.2 / 1.5 是字符口径）；
- 声调不同：+0.1（只影响多音字候选的排序，不改变命中与否）；
- `span`：从首个命中音节到识别文本末尾的音节数；
- `confidence = 1 - spanError / span`：**命中区间内的音节一致率**（1 = 每个音节都对上，0 = 全错）；
- 闸门阈值保持 `confirm 0.55 / weak 0.35`，10 段评测复核无需调整（分桶见第 4 节）。

## 3. 10 段评测同口径对照

### 3.1 同一环境（今日、宿主机 arm64、同模型 zipformer-zh-14M-int8、同 20 ms 分片）

| 口径 | CER | 命中率 | 首字 P50/P95 | 跟随 P50/P95/均值 | 误触发 |
| --- | --- | --- | --- | --- | --- |
| 读音（默认） | 11.6% | **100.0%（39/39）** | 460 / 780 ms | 877 / 1626 / 946 ms | 0 |
| 文字（开关关闭） | 11.6% | 97.4%（38/39） | 460 / 780 ms | 877 / 1626 / 946 ms | 0 |

结论：同一 ASR 输出下，读音匹配多命中 1 段，延迟不变，误触发不升。

### 3.2 与 0.24.0 基线对照（跨环境，仅作参考）

| 版本/口径 | CER | 命中率 | 首字 P50/P95 | 跟随 P50/P95 | 误触发 | 最大越级 |
| --- | --- | --- | --- | --- | --- | --- |
| 0.24.0 基线（宿主 x64） | 12.0% | 87.2%（34/39） | 460 / 780 ms | 1320 / 5734 ms | 0 | 0 |
| 0.25.0 读音（宿主 arm64） | 11.6% | **100.0%** | 460 / 780 ms | 877 / 1626 ms | 0 | 0 |

**实测与推断分开**：命中率、跟随延迟的改善是本轮改动后的实测；但基线是 x64 宿主、今日 arm64 宿主，ASR 识别文本本身有细微差异（如「停顿两秒左右」vs「停顿量秒事」），因此 CER 12.0→11.6 不能全部归因于匹配层。严格同环境的权威对照是 3.1 的读音 vs 文字。

逐段原始报告：`teleprompter/build/eval-025-phonetic.json`、`teleprompter/build/eval-025-literal.json`。

- 方法：30 分钟数字静音 WAV（16 kHz 单声道，1800 s），走同一套真机 ASR + 对齐 + 闸门；脚本 20 行全部标注为未朗读，任何锚点推进都计为误触发。
- 结果：**误触发 0 次、锚点移动 0 行、误触发/分钟 0.0**；RTF 1.064（30 分钟音频约 32 分钟跑完，符合实时节奏）。
- 原始报告：`build/device-silence-30m.json`（汇总：`falseTriggers: 0, falseTriggerPerMin: 0.0, distance: 0`）。
- 说明：数字静音比真实房间底噪更"干净"，真人环境底噪仍需现场复核；本项只证明"无语音输入时不会自行推进"。
