# 0.27.0 跟随判定与阅读页视觉：实测记录（2026-11-11）

- 结论：**识别侧读音单一口径、连续朗读自适应、跳读 3 行硬上限、阅读页视觉清理为「实测通过」；行级覆盖放行、端到端延迟补偿为「已接入且有单测/同口径对照，但现有评测集无可测收益」。**
- 环境：宿主机 macOS（arm64，Flutter 3.47.9 / Dart 3.13.7），模型 `zipformer-zh-14M-int8`，评测集 `teleprompter/eval`（10 段），分片 20 ms，单线程 greedy。设备 `f37aa514`（Android 15）用于截图。

## 1. 识别侧

### 1.1 匹配只走读音

- 台本与识别结果统一归一化为拼音音节，等价类在先前的 `zh/ch/sh → z/c/s`、`n/l`、前后鼻音基础上新增：
  - 唇齿/喉擦混读：`f → h`；
  - 边音/卷舌近音：`r → l`；
  - 韵母混读：`uang/uan`、`iang/ian`、`ing/in`、`eng/en`、`ang/an`、`iu/ou`。
- 音节级近似：`Normalizer.nearSyllable` 允许**声母相同**、编辑距离 ≤ 1 的漏读/多读/替换（`tian ↔ tuan` 等价，`tian ↔ xian`、`tian ↔ ting` 不等价）；英文 token 不参与。
- 判定顺序：模糊等价 → 多音字候选集合求交 → 非拉丁 `nearSyllable`。声调只影响 DP 代价（+0.1），不是硬条件。

### 1.2 移除「按读音近似匹配」开关

- 删除 `MatchMode`、`Normalizer.mode`、`normalizer_text` 分支与 `AlignEngine` 的 normalizer 注入；设置页开关与文案（中英 ARB）一并删除。
- 旧预设：`phoneticMatch` / `matchMode` 读入忽略，`toJson` 不再输出（`reader_settings_test` 有「旧预设已移除开关被忽略且不写回」用例）。

### 1.3 连续朗读自适应（三档保留）

- 进入：连续 5 次合格更新（置信 ≥ 0.35）且 8 s 窗口内锚点推进 ≥ 3 行、相邻输出间隔 ≤ 2.5 s。
- 退出：> 2.5 s 无输出，或连续 3 次低于弱阈值。
- 放宽量：`confirm 0.55 → 0.47`、`weak 0.35 → 0.27`、`weakHits 2 → 1`；切换时清空弱命中累计，避免用旧阈值攒的次数跨档使用。
- **保留三档、只做自适应微调的理由**：档位是用户对「口误容忍 ↔ 抢行」的偏好，严格档要的是保守、宽松档要的是不卡；纯自适应会让同一台设备的行为不可预测，也无法解释「为什么今天更容易抢行」。自适应只在档位基线上做固定 -0.08 的微调，档位仍是唯一可解释、可回退的开关。

## 2. 跟随时机

### 2.1 端到端延迟补偿

- 估计量 = 采集分片 40 ms + 识别解码 `decodeMs`（**实测值**，来自 ASR 引擎每次输出）+ 一帧 16.7 ms；EMA 平滑（旧值 0.8 / 新值 0.2）。
- 前馈：`leadRows = clamp(estimateMs/1000 × 语速, 0, 0.8)`，语速为最近行推进速率的 EMA（0–4 行/s）。滚动目标在「当前行 → 下一行」之间插值提前，锚点行本身不提前。
- 可观测：每 5 s 写 `voice/latency_compensation`（enabled / estimateMs / rowsPerSecond / leadRows）。
- 可关闭：设置项「跟随延迟补偿」（默认开），关闭即 `leadRows = 0`，回到基线。

### 2.2 跳读硬上限 3 行

- 新增不变量 `maxAutoLeapLines = 3`（`core_alignment/lib/src/limits.dart`），三处强制：
  1. `LineStepGate` 构造时把 `maxLeap` clamp 到 `[1, 3]`，宽松档 profile 由 4 改为 3；
  2. `AlignTracker.update` 先把候选行 clamp 到 `_line + 3`，被夹住时标记 `fastCatchUp`；
  3. `EarlyArmDetector` 命中校验后把目标行 clamp 到 `currentLine + 3`（含短尾捷径）。
- 测试：`line_coverage_test.dart` 内 5 个不变量用例（构造参数上限、tracker 夹行、早跨行夹行、短尾捷径、宽松档 profile）。

## 3. 判定单位：整行读音覆盖度

### 3.1 覆盖率怎么算

- `LineCoverageTracker`：分母 = 该行（**语义行/段落**）的有效音节数（数字按口播读法展开、英文术语整体一个 token），分子 = 识别流中命中的音节数；快照另带 `farthest`（最远命中下标）。
- **取语义行而不是视觉行的理由**：放行的对象是锚点行，锚点、断点、遥控坐标、录制时间轴都以语义行为单位；视觉行由字号/宽度/设备折行决定，同一句话在手机上可能是 2 行、在平板上 1 行，用它当分母会让同一段朗读在不同排版下判定不同。代价是超长段落分母大、放行更依赖阈值分档，因此下面用「长度分档 + 最远位置」补偿。

### 3.2 防作弊（双条件 + 单调）

- 条件一：覆盖率 ≥ 分档阈值；条件二：`farthestRatio ≥ 0.6`（最远命中必须落在本行 60% 之后）；条件三：至少命中 3 个音节。
- 行内命中**必须单调前进**，允许一次跳过错过的音节最多 3 个（`skipWindow = 3`）。
- 噪声为何不易触发：随机的同音命中要同时满足「60% 以上音节」「最远位在 60% 之后」「顺序单调」「对齐已给出下一行读音」「对齐置信 ≥ 弱阈值」——前四条把「零散命中堆分子」和「只读行尾关键词」都堵掉，最后一条保证触发时音频里确实出现了下一行的内容。

### 3.3 行内顺序

- 要求单调。允许乱序时，重复口头语（「目标是，目标是」）、ASR 回显、口头填充词都会被计入分子；30 字长行阈值只有 65%，乱序下凑够的概率明显上升，且无法用「最远位置」兜底（乱序意味着最远命中本身不可信）。

### 3.4 短行与长行

- 分档：≤5 音节 0.9；≤12 音节 0.8；≤25 音节 0.72；>25 音节 0.65。短行 1 个字权重太大，5 音节行 4/5 = 0.8 不放行、必须 5/5；长行允许 35% 漏读。

### 3.5 与自适应、3 行上限、延迟补偿的叠加

- 顺序：行级覆盖判定 → 目标行 `min(alignLine, anchor + 3)` → 前馈插值 → 滚动。
- 三条互不改写：覆盖放行不提高 `maxLeap`（仍受 3 行不变式）；`relaxed` 只改逐字闸门的阈值，不改覆盖阈值；补偿只改滚动目标，不改锚点行与放行判定。
- 误触发与抢行是最需要盯的两条，见第 5 节。

### 3.6 字符级锚点的定位

- `_advanceTo(target, alignChar)` 仍回填字符偏移，供坐标、进度条、遥控、录制时间轴使用；**放行只看行级覆盖度，字符偏移不再参与放行判定**。

### 3.7 关键取舍：覆盖放行只在「对齐已跨行」时生效

- 第一版让「覆盖率达标 + 连续语音」在行内直接滚行，`p0-zh-pause-01` 在句末 2.4 s 停顿里滚到了下一行 → 误触发 0.8/min。
- 第二版加「下一条更新确认」后更差（2.5/min）：确认用的那条更新往往就是句末 `isFinal`，它必然落在静音跨度里。
- 最终版：行内只累计覆盖、不滚行；对齐出现下一行读音（`alignLine > anchor`）且覆盖达标 → 立即放行，跳过闸门的逐字连续命中/弱命中累计。这样「行内漏读不卡跟随」成立，同时静音守线回到 0。

## 8. 结论分类

**实测通过**

- 读音单一口径（含 f/h、r/l、韵母混读、音节编辑距离）；开关与文字分支移除，旧预设兼容。
- 连续朗读自适应、跳读 3 行硬上限（含测试）。
- 延迟补偿：P50/P95/均值各 -40 ms，误触发与抢行不变。
- 阅读页视觉与设置项清理。

**仅接入未验证**

- 行级覆盖放行在真人漏读/跳词场景的收益（现有评测集为照稿朗读，无可测差异）。
- 行级覆盖与自适应同时处于放宽态时的叠加行为（评测集未触发放宽态）。
- 1.5 px 下划线在 24/44/160 px 字号与四组镜像下的观感（本记录只出 44 px 截图）。
- 真实环境音 30 分钟（本记录为数字静音）。
