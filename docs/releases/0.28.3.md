# 0.28.3（2026-11-12）

> 状态：**已出 release** ｜ 平台：Android（APK） ｜ 版本口径：`version: 0.28.3+2037`
> 主题：语音跟随「位置锁死 / 抢跑」修复 + 短跨度跳跃收紧（0.28.2 逐行吸附手感改动一并进包）

## 这个版本能做什么

- **手动拖动、手动跳行、回到篇首之后，语音跟随能接着当前页面继续**：不再出现「页面停住、识别文本还在走」。
- **读快时不再抢跑**：2–3 个音节的偶然同音不会再让页面一次跨过三段；页面位置与朗读位置保持同步。
- 0.28.2 的逐行吸附手感保持：单行 500 ms `easeOutCubic`，追加行 160 ms，单段 ≤1 行。
- 红线条数与阈值均未放宽：单次 ≤3 行、任意 10 秒累计**跳行** ≤3 行、误触发 0。

## 根因（2026-11-12 诊断）

页面锚点、`AlignTracker` 行号、对齐窗口三者会失步，且失步后无法自愈：

1. 对齐窗口起点取的是 `tracker.line`，而手动滚动只改页面锚点，两者分叉后窗口整体错位；错位时 `cost ≈ span`、置信度 0.07–0.10，被 `acceptFloor = 0.2` 永久拦下。
2. 反方向（页面在前）时，候选永远小于锚点，被闸门的单调性 `heldBack` 永久拦下。
3. 快读时识别错误率上升，`span = 3`、`conf ≈ 0.67` 的偶然命中会触发 3 行越级，把锚点推到朗读位置之前，之后同样的失步就锁死。
4. `AlignTracker.reset()` 不清 `_line`，跳行后跟踪器仍停在旧位置。

## 修复

- 对齐窗口起点改为**页面锚点**（`anchorCharLine`），跟踪器只作兜底。
- 手动拖动/甩动、手动跳行、回到篇首、重开语音时 `tracker.forceLine(_anchor)`；`AlignTracker.reset()` 一并清 `_line`。
- `span < 6` 或 `conf < 0.8` 时单次只允许 +1 行（跟踪器、闸门、覆盖率、失败重定位四条通道统一由 `leapCapForEvidence` 夹住）。
- 回放路径音频结束后补 600 ms 尾音再 flush，避免结尾短句整句丢失；麦克风实时路径不加假 final（见已知问题）。
- 删除 `diag/voice` 中的识别原文，只保留计数/行号/置信度（CODING §7）。

## 已知问题 / 待验证

- **60 秒与 45 秒档尾句未到末行**：两条都停在 11 行（「……来自人的习惯。」），识别器始终没有产出「谢谢大家」这 4 个音节；70 / 55 / 49.6 s 三条能到 12 行，其中 70 s 迟到约 8.8 s。
- **45 秒档出现 10 秒推进 4 行**：9.1 s → 19.0 s 由 1 行到 5 行，超过「10 秒累计跳行 ≤3」的口径（逐行推进不计入预算，本次按要求没有按总前进行数收紧）；该段与语音 2.7 行/10 s 不符。
- **尾音补偿在 release 包里不生效**：`VoiceFollowSession.startReplay` 的唯一调用方是 debug 的「回放测试音频」按钮，release 构建把整条回放路径 tree-shake 掉，`libapp.so` 内查不到 `finishWithTail`。麦克风实时路径按设计不加假 final，因此该修复只对开发回放有效。
- **真人录音语料仍为空**：本版所有数字来自 5 条合成语料（`say` + `atempo`，经 Mac 外放进手机麦克风），只代表时序与对齐链路，未据此下任何识别质量结论。
- **原 0.28.3 内测包为 Android Debug 证书签名**（`C=US, O=Android, CN=Android Debug`），仅供内测安装；GitHub Release 已用仓库外 release keystore 重新签名，见下节。
- release 包不可 `run-as`，应用私有日志无法用 adb 直接读取；本版验收以 UI、`dumpsys package`、`aapt2`、`apksigner` 与 `libapp.so` 字符串为准。
