# 0.28.1（2026-11-11）

> 状态：**已出 release** ｜ 平台：Android（APK） ｜ 版本口径：`version: 0.28.1+2034`
> 主题：提词页滚动连续化（去整行吸附、单档限速、松手惯性），并作为 **0.28.0 五项改动的首个发布包**

## 这个版本能做什么

- **滚动不再「吸」到某一行**：跟随、手动匀速、语音推进三条路径共用同一套像素级平滑；滚动位置是连续量，视觉上不再一行一行跳。
- **松手有惯性**：手滑后按松手速度自然减速，触边即停，不再被程序拽回整行边界。
- **五档识别宽松度**：`veryStrict / strict / standard / loose / veryLoose`，只显示档位名与一句用途说明。
- **台本只有一整段连续正文**：新建、编辑、导入都不再分段，编辑器只有一个正文输入框。
- **默认中文轻量 14M 模型**：开箱即用；中英混合 209 MB 模型仍可在设置中切换。
- **左右边距独立**：左边距、右边距分别设置并持久化。
- **提词页单栏功能栏**：默认只保留上一行 / 播放暂停 / 下一行 / 麦克风，其余按钮可在设置中勾选。

## 滚动改造（本版核心）

### 根因：不是掉帧，是目标被整行量化

真机应用内 `FrameTiming` 插桩显示，改前手动匀速会话 p95 total 8.92 ms（janky 23 帧）、拖动 6.59 ms（janky 9 帧），都在 16.7 ms 预算内；日志 `asr_lag.backlogMs = 0`、RTF 0.058–0.071，识别也没有拖后腿。真正的顿挫来自三处整行落位：

1. 手动松手后 `jumpTo(整行)`，松手即吸附；
2. 语音目标只取 `rowForChar` 的整行号，行内字符推进不改目标，攒满一行才跳；
3. 舞台缓存键包含 `anchorRow`，每跨一行重建整篇正文。

另外旧跟随器有「常态 / 追赶」两档速度（600 / 1200 px/s），追上目标时回落，形成「先快后顿」。

### 修复

- `LayoutSnapshot.rowPositionForChar` 返回「行号 + 行内字符进度」，滚动目标改为分数行。
- `ReadingFollower` 统一为一阶指数逼近（`tau = 70 ms`），**只保留一档 2400 px/s**；删除追赶档。
- 手动松手改为 `fling(velocity)`：450 ms 时间常数指数衰减，触边即停；只有显式跳转或目标距离 >8 行才直接落位并做 120 ms 淡入。
- 舞台缓存键去掉 `anchorRow`，常规跟随不再重建正文；当前行指示改为固定屏幕空间的阅读带下划线。

## 升级注意事项

- 覆盖安装即可，无需卸载；实测 0.27.2 → 0.28.1 数据保留，台本、上次阅读时间、设置均未丢。

- 「宽松度」旧三档名称仍是新五档中的合法值，其余旧值按默认档处理，不报错。
