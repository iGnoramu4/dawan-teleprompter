# 大皖提词器 · 项目说明

> 适用版本：`0.28.3+2037` ｜ 更新：2026-11-12 ｜ 维护者：吃不饱
> 本文是面向新访客、使用者与贡献者的项目级说明。规范与流程以 [docs/README.md](./README.md) 为准，构建细节以 [BUILDING.md](../BUILDING.md) 为准。

## 1. 项目定位

大皖提词器是一个**以本地流式语音识别为滚动驱动**的跨平台提词器。它解决的不是“把字放大显示”，而是“讲话人不看屏幕、不碰设备时，稿件如何始终停在下一句要念的位置”。

一句话差别：

> 普通提词器按固定速度滚；大皖提词器**听你读到哪里，就把画面推到哪里**，识别、对齐、滚动与存储全部在本机完成。

### 1.1 目标用户

| 用户 | 场景 | 关键诉求 |
|---|---|---|
| 短视频 / 直播创作者 | 手机或电脑前口播，同时看评论与素材 | 悬浮提词、手机遥控、录制同步 |
| 讲师 / 培训师 | 教室投影 + 讲台设备 | 外接显示、大字号高对比、稳定跟读 |
| 会议 / 演讲者 | 舞台、分光镜提词器 | 镜像、暗色、低延迟、抗回声 |
| 企业宣传 / 客服 | 固定话术录制 | 台本管理、Word/PDF 导入、时间轴导出 |

### 1.2 非目标

云同步、账号体系、云端识别、在线埋点、AI 改写、多人实时协作、AR 眼镜、直播推流、实时字幕输出。iOS 与 Linux 不在本期交付范围，架构保留扩展位。

## 2. 与普通提词器的差别

| 维度 | 普通提词器 | 大皖提词器 |
|---|---|---|
| 驱动方式 | 定时匀速滚动，手动调速 | 语音识别驱动；停顿停住，跳读能追上 |
| 匹配方式 | 无 | 按读音（无声调拼音音节）对齐，覆盖常见混淆音 |
| 网络依赖 | 常需账号或云服务 | 识别、对齐、存储、诊断全本地 |
| 防跳读 | 无统一约束 | 单次 ≤3 行、10 秒累计跳行 ≤3、失败重锚 ≤3 且需冷却 |
| 阅读位置 | 整行跳动 | 固定阅读带 + 语音逐行吸附；触控保持连续像素滚动 |

## 4. 技术架构

### 4.1 总体

分层 + 模块化单体（Monorepo，多包）。三端共享 Dart 业务与 UI；平台能力经插件或 MethodChannel 下沉到原生。核心算法（模型、对齐、阅读布局、录制时间轴）为纯 Dart，可脱离 Flutter 单测。

### 4.2 目录职责

| 路径 | 职责 |
|---|---|
| `apps/app/` | Flutter 应用壳：路由、feature 页面、共享状态、数据装配（Android / macOS / Windows） |
| `packages/` | 本地 Dart/Flutter 包，`publish_to: none`；核心算法与基础设施 |
| `tool/` | 工程检查、许可扫描、图标生成、模型清单、宿主评测与真机评测壳 |
| `eval/` | 评测集：台本、标注、清单；音频由脚本生成，不入库 |
| `assets/` | 品牌图标母版与三端产物；已否决的 proposals 不入公开仓库 |
| `docs/` | 规范、架构、设计、接口、测试记录、发布说明、用户手册、法务文本 |
| `dist/` | 本地发布 APK 与 `SHA256SUMS`，被 `.gitignore` 排除 |
| `models-eval/` | 本地评测权重，被 `.gitignore` 排除 |

### 4.3 包职责与依赖

| 包 | 职责 | 依赖 | Flutter |

| `core_alignment` | 归一化、拼音、模糊等价、预筛、窗口单调 DP、闸门、跳读预算 | `core_models`、`lpinyin` | 否 |

| `core_recording` | 录制时间轴：10 Hz 采样、线性插值、SRT 导出 | `core_models` | 否 |

1. `core_*` 不得 import Flutter、`dart:ui` 或任何插件；
2. `features/<a>` 不得 import `features/<b>`（跨 feature 必须下沉到 `packages/` 或 `apps/app/lib/shared/`）；
3. `lib/shared/` 不得反向 import `features/`；
4. `packages/*` 不得 import 应用代码（`package:teleprompter/` 或跳出包 `lib` 的相对路径）；
5. `design_system` 不得 import 业务包（`data_store`、`asr_kit`、`core_*`）。

> [ARCHITECTURE.md](./architecture/ARCHITECTURE.md) 已按当前实际包结构同步；若与本节再次出现冲突，以 `packages/` 实际目录与 `check_imports` 规则为准。

### 4.4 关键数据流

**台本导入**

```
文件 / 剪贴板 / .tps
  → document_import（MIME 嗅探、大小限制）
  → 清洗（硬换行、页眉页脚、全半角、Markdown）
  → 预览确认
  → data_store 事务写入 scripts / sections / markers / presets
```

**语音跟随**

```
麦克风 16 kHz / mono / PCM16
  → asr_kit 流式识别（partial / final + 端点）
  → core_alignment 归一化 + 拼音 + 预筛 + DP + 覆盖度闸门
  → AlignTracker / 跳读预算
  → core_reader_layout 视觉行坐标 + 固定阅读带
  → 单处 Transform.translate 渲染
  → 诊断记录（不记识别原文）
```

**遥控**

```
主控端分配语义行号 + 视觉行坐标
  → WebSocket JSON（配对 token、心跳、鉴权）
  → 遥控端只显示行号/文本切片，不做像素换算
  → 上行 cmd → 主控执行 → ack
```

**录制**

```
同一 PCM 流扇出
  → WAV 文件 + 10 Hz 时间轴（t → 段落/字符）
  → 回放按播放位置驱动同一 ReaderState
```

### 4.5 会话状态机

```
idle ──start──► loading ──ready──► following ⇄ paused
                  │                   │
                  └──error──► error ◄─┘（麦克风失败 / 模型缺失 / 权限拒绝）
```

- 手动接管：`following → manual`（手势 / 遥控），无语音或用户恢复后回到 `following`；
- 低置信：在 `following` 内降速，不切状态；连续多次低置信回到手动并提示；
- 状态变化只经由 `Notifier`，UI 不直接改状态。

## 5. 语音跟随原理

### 5.1 音频与识别

- 采集：16 kHz、单声道、PCM16，Android 使用 `VOICE_RECOGNITION` 音源；录制与跟随共用同一条流。
- 识别：sherpa-onnx 流式 zipformer，逐分片返回 partial，端点后返回 final。
- 解码在独立 isolate 中执行，不阻塞 UI；模型首次使用时从 assets 解包到应用私有目录。

### 5.2 归一化与拼音

- 归一化处理标点、全半角、繁简、英文大小写、数字读法；只保留可读内容。
- 中文一字一音节，英文术语整体一个 token；比较使用**无声调拼音**，声调仅作 0.1 的小幅加分。
- 多音字按词表/上下文取音；无法确定时保留多个候选。

### 5.3 模糊等价

常见普通话混淆对：

| 类型 | 等价关系 |
|---|---|
| 平翘舌 | `zh/ch/sh → z/c/s` |
| 鼻音/边音 | `n ↔ l`、`r ↔ l` |
| 前后鼻音 | `ang/an`、`eng/en`、`ing/in` |
| 唇齿/喉音 | `f ↔ h` |
| 韵母 | `uang/uan`、`iang/ian`、`iu/ou` |
| 音节近似 | 声母相同且编辑距离 ≤ 1 |

匹配单位是**音节**，不是汉字；因此“读错声调”“平翘舌不分”“前后鼻音不分”不会直接导致对不上。

### 5.4 窗口单调 DP 对齐

- 先做命中率预筛，缩小候选行范围；预筛接管需要置信 ≥ 0.5 且领先 ≥ 0.2。
- 在有限窗口内做单调路径 DP，带宽 `|i-j| ≤ 40` 音节。
- 窗口起点取**分句起点**：端点重设；文本公共前缀 < max(3, 上次长度 × 0.5) 视为新分句；阅读位置远超“分句起点 + 文本长度”可解释范围时作废旧起点。
- DP 首行台本前缀免费跳过（`dp[i] = 0`）。
- 窗口长度自适应：`n = min(reachable, max(windowW, m + 2 × band))`，上限 600 音节。带宽只约束分句内部局部错位，不再把长分句整体判成假路径。
- 对齐窗口起点使用**页面锚点**（`anchorCharLine`），跟踪器行号只作兜底；手动拖动、跳行、回到篇首、重开语音时同步 `tracker.forceLine(anchor)`。

### 5.5 整行读音覆盖度闸门

放行单位是**整行读音覆盖度**，不是逐字命中：

- 按行长分档阈值：0.9 / 0.8 / 0.72 / 0.65；
- 要求最远命中 ≥ 行内 60%；
- 要求行内单调前进；
- 行内字符偏移只用于坐标、进度与录制时间轴，不参与放行判断；
- `span < 6` 或 `conf < 0.8` 时单次只允许 +1 行。

### 5.6 跟踪器与跳读三重约束

1. **单次上限**：任何一条自动推进通道（闸门、跟踪器、提前跨行、失败重定位、覆盖率）单次最多 +3 行。
2. **时间窗口累计**：`AutoAdvanceBudget` 在 10 秒窗口内限制跳行总和 ≤ 3；预算用尽后只允许 +1 逐行推进。逐行推进不计入预算，否则正常朗读会长期处于用尽态。
3. **失败重锚冷却**：重新锚定单次 ≤ 3 行，且只能落在已读位置之后、不超过当前行 +3 行；重锚后需 3 次正常命中才允许下一次重锚；超出范围只更新置信，不移动位置。

另外：候选行必须大于当前行（单调性）；口误/重复默认不回跳，避免“读错一句，页面向后退”。

### 5.7 阅读带与滚动

- 阅读带位置由 `readAheadRatio` 控制，默认 0.34（34%），可调 0.2–0.6。
- 渲染层只有一处 `Transform.translate(0, -position)`，不触发文本重排；视觉行几何来自 `LayoutSnapshot`。
- **语音跟随**：目标是整视觉行；`ReadingFollower.snapTo` 用 `easeOutCubic` 把目标行吸到阅读带下划线。第一行 500 ms（平滑度 4–12 映射 550/500/450 ms/行），同一段连续吸附从第 2 行起每行 160 ms，单段位移 ≤ 1 行，段末速度为 0。
- **跨多行追赶**：2 行约 660 ms、3 行约 820 ms；仍逐行落位，不跳过中间行。
- **触控**：`nudge` / `fling` 直接改连续像素位置，不做整行量化、松手不吸附；识别暂停或关闭时冻结跟随器，正在进行的吸附立即取消。
- **远距离跳转**：显式跳转或目标距离 > 8 行时直接落位并做 120 ms 淡入。

### 5.8 延迟预算结论

0.27.2 的端到端拆解（同环境）：

| 环节 | P50 | P95 |
|---|---|---|
| 采集分片 | 80 ms | 80 ms |
| 音频线程排队 | 0 | 0 |
| 单次解码 | 0.0 ms | 3.2 ms |
| 对齐 DP（每次 partial） | 58 µs | 384 µs |
| 产生新行 → 重绘 | 一帧内 | 约 7 ms |
| **ASR 出字间隔（最大项）** | **320 ms** | **1280 ms** |

结论：跟随延迟的主要来源是模型 chunk 决定的出字节奏，不是解码、对齐或渲染算力。单纯提高线程数或做增量对齐收益极低，不值得以正确性风险换取。

## 6. 构建与运行

### 6.1 环境

见 [BUILDING.md](../BUILDING.md) §1。要点：

- Flutter 3.47.9 stable，Dart 3.13.7；Apple Silicon 使用 arm64 SDK。
- Android：JDK 17 + Android SDK；`minSdk 24`、`targetSdk 36`。
- macOS：macOS 12+、Xcode 16+、CocoaPods。
- Windows：Windows 10/11、Visual Studio 2022（Desktop development with C++）。
- Python 3.10+ 仅在重新生成图标时需要。

### 6.2 拉取依赖

```bash
cd teleprompter
flutter pub get
cd apps/app
flutter pub get
```

### 6.3 准备模型权重

仓库不含 `.onnx` 与 `tokens.txt`。按 [models.lock.json](../teleprompter/tool/models.lock.json) 下载并放置：

```
teleprompter/apps/app/assets/models/zipformer-zh-14M-int8/
teleprompter/apps/app/assets/models/zipformer-bilingual-mixed/   # 可选
```

要求：

1. 文件名、字节数与清单一致；
2. `shasum -a 256` 与清单一致；
3. 双语模型必须使用 encoder int8 + decoder/joiner fp32，不要替换为全 int8。

### 6.4 运行与构建

```bash
cd teleprompter/apps/app
flutter devices
flutter run -d <device-id>

flutter build apk --release
flutter build macos --release
flutter build windows --release
```

发布、签名、公证与回滚见 [发布手册](./ops/release-runbook.md)。

### 6.5 已知构建环境坑

| 现象 | 处理 |
|---|---|
| `flutter analyze` 在含中文/空格路径下崩溃 | 改用 `dart analyze`，并在 `apps/app`、`packages/*` 内分工作区执行 |
| x86_64 Flutter SDK 在 Apple Silicon 上 `flutter test` 失败 | 使用 arm64 SDK；不要经 Rosetta 调 `xcrun` |
| Android 构建报缺少 `local.properties` | 由 Flutter/Gradle 生成，不要提交 |
| 启动后提示模型缺失 | 按 §6.3 放置权重并校验 SHA256 |
| 浮窗/外接屏不显示 | 确认 Android 权限与有线扩展屏；无线投屏通常是镜像 |
| 换包名后无法覆盖安装 | 包名变更即全新应用；旧数据不迁移，需卸载旧包 |

提交前检查见 [docs/README.md](./README.md) §4，覆盖率门槛 70%，`core_*` ≥ 85%。

|---|---|

### 8.3 指标口径

| 指标 | 定义 |
|---|---|
| CER | 归一化后 token 编辑距离 / 参考 token 数 |
| 首字延迟 | 每行开始 → 第一条包含新内容的 ASR 结果到达（音频时间轴） |
| 跟随延迟 | 每行开始 → 锚点首次到达该行 |
| 跟随命中率 | 每行结束 +600 ms 时锚点是否 ≥ 该行 |
| 误触发/分钟 | 静音区间内锚点越过已读行的次数 / 静音分钟数 |
| 抢行 | 任一时刻 `锚点行 − 应读行` 的最大值 |
| 单次最大跳行 | 一次自动推进跨过的行数 |
| 10 秒累计跳行 | 任意 10 秒窗口内自动跳行总和 |
| RTF | 解码总耗时 / 音频时长 |

红线：单次 ≤ 3 行、任意 10 秒累计跳行 ≤ 3、30 分钟静音误触发 0。当前 10 段合成语料实测三项均为 0。

## 10. 路线图

1. **真实语料**：先建 ≥10 段真人录音，再扩到 60 段；没有真人语料不调识别阈值。
2. **0.28.3 遗留**：尾句未到末行、快读片段 10 秒推进 4 行；先取证，再权衡追赶速度与红线。
3. **真机联调**：外接屏与遥控（两台设备）、悬浮窗手感、低存储解包失败路径。
4. **桌面端**：完成 macOS/Windows 构建与装机验证；补 Windows 复盘播放。
5. **发布工程**：正式签名、商店合规、CI 接入 golden/集成测试与评测基线。
