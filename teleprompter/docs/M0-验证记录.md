## 4. Android 实测

### 4.1 构建与安装

```bash
cd teleprompter/apps/app
~/flutter-sdk/arm64/flutter/bin/flutter build apk --release --target-platform android-arm64 --split-per-abi
adb install build/app/outputs/flutter-apk/app-arm64-v8a-release.apk
```

- 产物（全部实测安装运行）：
  - debug 通用包 `app-debug.apk`：189 MB
  - release 通用包 `app-release.apk`：115.5 MB（含全部 ABI）
  - release arm64 分包 `app-arm64-v8a-release.apk`：65.4 MB
  - 体积主要来自 sherpa-onnx 全部 ABI 动态库与 24 MB 模型；arm64 分包已把 ABI 裁剪到单架构。
- 设备：`emulator-5554`，arm64-v8a，API 36。
- 备注：首次遇到构建失败时可用 Gradle 直连 `./gradlew assembleDebug -Ptarget-platform=android-arm64` 作为兜底。

### 4.2 界面链路（已逐项点击验证）

- 首页：3 篇内置台本，Material 3 深色主题，标题/字数/M0 标记正常。
- 阅读页：台本逐行渲染、当前行高亮（深底 + 左侧琥珀色竖条）、右上角 `行号 / 总行数`。
- 滚动：默认 1.2 行/秒自动上滚；暂停按钮点击后停留在第 1 行不再移动，图标切为播放；再次点击恢复。
- 调速：连点两次减号，标签从 `1.2 行/秒` 变为 `0.8 行/秒`。
- 字号：`A- / A+` 与字号标签存在，本次未逐档点击（M0 只要求调速与暂停）。
- 横竖屏/沉浸式：进入阅读页隐藏系统状态栏与导航栏。

修复记录：初版阅读页把上下留白（0.35 + 0.65 视口高）写成 `Padding`，导致正文可用高度为 0、全屏黑屏；改为 `OverflowBox` + 顶部/底部占位后正文正常显示。

### 4.3 语音跟随（WAV 回放，离线）

测试音频：`assets/test_wavs/demo_zh.wav`（16 kHz mono PCM16，5.2 s），台本 `demo_follow.txt` 三行。

真机日志（`adb logcat`，tag `I/flutter`，节选）：

```
M0-ASR ready loadMs=336
M0-ASR t=713ms  text="重点"                       line=0 conf=1.00 decode=4.53ms
M0-ASR t=1672ms text="重点呢想谈三个问题"           line=0 conf=1.00 decode=4.97ms
M0-ASR t=2633ms text="重点呢想谈三个问题首先"       line=1 conf=1.00 decode=4.64ms
M0-ASR t=3273ms text="...首先呢就是"               line=1 conf=0.38 decode=5.07ms
M0-ASR t=4872ms text="...这一轮全球金融动量的表现"  line=1 conf=0.66 decode=5.36ms
```

- 模型加载：334–336 ms（模型已落盘到应用私有目录；全新安装的 release 包同样是 334 ms）。
- 单块解码：4.5–8.0 ms，音频块 32 ms → RTF 约 0.15–0.25（模拟器 CPU，未开多线程调优）。
- 首字延迟：音频开始后约 0.71 s 出现第一段识别文本（流式输出的第一块命中）。
- release 包（AOT）复测：同为 `ready loadMs=334`、首字 713 ms、2.63 s 跳到第 2 行，行为与 debug 一致。
- 对齐跳行：第 2 句"首先"在 t≈2.63 s 被识别，高亮与滚动游标同步从第 1 行切到第 2 行；截图中第 2 行完整高亮，页面显示 `2 / 3`。
- 置信度：第 1 行 1.00，第 2 行随匹配进度 0.33 → 0.66，符合"部分匹配时偏保守"的预期。
- 回放结束：状态卡显示识别全文、置信 63%、解码 5 ms、首字 4879 ms。

- 模型：`assets/models/zipformer-zh-14M-int8` 共 24 MB（encoder 21.6 MB + decoder 1.8 MB + joiner 1.8 MB + tokens 49 KB）。

## 5. 阻塞与原生缺口

1. `flutter build apk` 一度失败，已定位并解决
   - 现象：报错 `xcrun: error: unable to load libxcrun ... (have 'arm64,arm64e', need 'x86_64')`，随后 `:app:compileFlutterBuildDebug` 退出码 1。
   - 根因：切换 SDK 前由 x86_64 Flutter 启动的 Gradle 守护进程残留，其子进程以 Rosetta 方式拉起 `xcrun`，与本机仅含 arm64 切片的 CommandLineTools 冲突。
   - 解决：执行 `./gradlew --stop` 结束旧守护进程后，`flutter build apk` 恢复正常，无需再走 Gradle 直连。
   - 教训：更换 Flutter SDK 架构后必须重启 Gradle 守护进程。
2. `flutter analyze` 在含中文与空格的工程路径下会崩溃（analysis server 退出 255），改用 `dart analyze` 正常。
3. macOS：缺少 Xcode 与 CocoaPods，构建被 Flutter 直接拦截。
4. Windows：Flutter 拒绝在 macOS 上交叉构建，需 Windows 宿主。
5. sherpa-onnx 插件默认打入全部 ABI，通用包偏大（release 115.5 MB）；`--split-per-abi` 后 arm64 包 65.4 MB，已实测可用。若要进一步压缩，可在 Gradle 里限定 `abiFilters` 并评估模型量化。
6. 当前仅 14M int8 中文模型（体积小、速度优先）；更大模型（如 multi-zh 系列）下载受阻，未对比准确率。
